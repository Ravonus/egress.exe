# Chromatic transfer optimization — 2026-10-15

Deployed the EGRESS writer optimization and shared phase timing display on both Chromatic pages. Canonical source c81d50447df21af1b5fcd066e46122ae252020c3; EGRESS site 5f4a63d; CRUCIBLE site caa4934. Public source: https://github.com/keel-web3/keel-engine/tree/codex/chromatic-transfer-verification/packages/chromatic (remote main had advanced, so no force push). CRUCIBLE currently has no enabled cartridge writer; its change is progress timing only. The site layouts, controls and theme are preserved.

The direct CBU1 writer already verifies the cartridge body with SHA-256/CRC32, then the withheld boot block by CRC32. The browser now recognizes completed verification phases and the exact job size/CRC completion followed by ready. This avoids a second entire ROM download. Firmware without completed-phase evidence retains full browser SHA-256 readback. The protected tail is checked before and after writing. Save readback remains mandatory. Receipt metadata identifies firmware-sha256-crc32 versus browser-sha256 and stores firmware phase durations. Duplicate local hash calculations were also removed; those were not the principal bottleneck.

Quantified transport reduction: an N-byte ROM without protected overlap saves N cartridge-read payload bytes and the entire redundant ROM-read command. For a 2 MiB image this removes 2,097,152 payload bytes (up to 2048 data frames), leaving the firmware verification intact. Sparse blank-bank compression can make the wire savings lower. This is a protocol-count result, not a measured physical speedup. Baud remains 115200: the supplied firmware explicitly rejects faster baud after hardware failures.

Validation: 37 unit/protocol tests passed; four native tests execute the supplied firmware's real command parser and verification code (correct ROM; corrupt body; wrong SHA with correct CRC; corrupt boot block). The native harness uses an in-memory cartridge bus and artificial time; it is not a whole-device simulation or speed benchmark. Both production builds passed. EGRESS: 9 browser tests passed, including full firmware-verification write/save flow, legacy fallback, optional backup, checkbox and reconnection. CRUCIBLE: 5 reconnection tests passed. Browser tests confirm phase time resets while total time continues. Screenshots are isolated browser-fixture evidence, not hardware evidence.

Deployment replaces only /chromatic HTML/RSC and static chunks. Guarded prior route hashes, backup /opt/velatis-gateway/backups/chromatic-speed-20261015. public-verification.json records exact live hashes for both pages and all published assets.

Observed hardware outcome: the user's existing EGRESS flash completed ROM verification but failed save readback. No agent write, retry, reload, disconnect or second device claim occurred. The firmware boots the game between commands (cf_esp.c:1846-1853); game-side SRAM changes are one possible cause, not proven for these bytes. This optimization does not suppress that mismatch or claim that the physical save restore is fixed. New optimized physical flash latency remains unmeasured.

Automatic approval review initially rejected applying the optimization for insufficient evidence linking completion to the ROM. The native firmware tests and CONTRACT.md established the command SHA binding and failure behavior; the subsequent reviewed application was approved.
